# Contributing

For routine updates, follow [Updating website content](docs/MAINTAINING-CONTENT.md).

1. Open an issue describing the correction or addition, affected page, and supporting source. A small typo fix may go straight to a PR.
2. Create a branch from the latest approved target branch. Keep content changes separate from layout or application changes.
3. Edit content and upload images. Never include credentials, private correspondence, or unapproved personal data.
4. Run the content checks and production build. Preview the affected list and detail pages on desktop and mobile.
5. Open a PR with a clear title, summary, sources, preview evidence, and actual test results. Mark unfinished work as draft.
6. Request at least one reviewer other than the author. Address requested changes; get approval for the latest revision.
7. Merge only when required checks pass, discussions are resolved, and an independent reviewer approves. Do not bypass checks or force-push protected branches.

These are contribution rules. Enforcement requires repository rulesets or branch protection; see [Review policy](docs/REVIEW-POLICY.md). This draft does not change repository settings or deploy the website.
